# Telegram-бот «Во сколько выходить» (MVP, СТАНКИН)

Группа + адрес один раз → расписание, заметка на день, два уведомления
(вечером «что завтра и что взять», утром «сколько ехать и во сколько выйти»).

Архитектура под будущее веб-/мобильное приложение: вся логика
(`schedule_client`, `normalize`, `buildings`, `geocode`, `routing_*`,
`metro`, `exit_time`, `store`, `notifications`, `service`) не зависит
от Telegram; `bot.py` — тонкий UI-слой.

## Реальный API stankinapp.ru (проверено живыми запросами 2026-09-24)
- `GET https://stankinapp.ru/api/groups` → `{"items": [...]}` — **286 групп**,
  `ИДБ-26-14` на месте. Эндпоинт нестабилен (таймауты TLS): клиент делает
  до 3 попыток, затем идёт каскад — `GROUPS_JSON_URL` (зеркало-JSON, любой
  формы) и `data/groups_cache.json` (сид из 286 групп уже в репозитории,
  обновляется при каждом успешном запросе).
- `GET /api/schedule?groupName=ИДБ-26-14&startDate=2026-09-24&endDate=2026-09-24` →
  4 пары сегодня (08:30 Фрезер 303(ММ), 12:20/14:05 ауд.0209, 15:50 ауд.0308);
  на 2026-09-25 → 3 пары (10:15 ИГ-1, 12:20/14:05 ауд.0209).
  Поля: `date/startTime/endTime/subject/teacher/type/cabinet/slotNumber/pairs`.
- ⚠️ **Флагов отмены/переноса в API нет.** Отменённая пара просто исчезает или
  меняется — бот это учитывает тем, что перечитывает расписание перед каждым
  расчётом и уведомлением (устаревшие уведомления не отправляются).
- Пустой день = выходной. Часовой пояс — `Europe/Moscow`.
- Параметры настраиваются (`SCHEDULE_GROUP_PARAM=startDate/...`), дефолты уже
  указывают на `https://stankinapp.ru`.

## Корпуса и кабинеты
API отдаёт только `cabinet`. Маппинг в `buildings.yaml`:
- `Фрезер*` → `шоссе Фрезер, 10` — точно (координаты сверены Nominatim+Photon);
- остальное (`0303`, `357(ж)`, `ИГ-1`, `Стадион 1`…) → `Вадковский пер., 3А`
  **эвристика** (помечается в ответе); координаты сверены (55.7901, 37.5957)
  и используются напрямую без геокодинга;
- пустой `cabinet` → «адрес неизвестен», время выхода НЕ выдумывается;
- API недоступен → расписание показывается как недоступное, без выдуманных времён.

## Расчёт дороги (проверено живыми запросами 2026-09-24)
Для `transit`: `дом —пешком→ ст. A —метро→ ст. B —пешком→ корпус`.
- **Пешком — настоящий пешеходный маршрут** (`routing_foot.py`, FOSSGIS
  `routing.openstreetmap.de/routed-foot`): 634 м за 507 с — честные 4.5 км/ч.
  ⚠️ `router.project-osrm.org` для пеших запросов сейчас **отдаёт автомобильное
  время** (проверено: 734 м за 104 с во всех профилях) — поэтому он оставлен
  только для авто/вело, пешком бот его не использует. Троттлинг 1.1 с + кэш 6 ч.
- **Метро — статическая оценка без расписаний** (`metro.py`,
  `data/metro_moscow.json`: OSM/Overpass, ODbL, 17 линий, 215 станций):
  `150 с посадка + Σ(длина/11 м·с + 30 с) + 300 с × пересадки`.
  Перебор **топ-3 входных × топ-3 выходных станций**, минимизируется полное
  время дверь-дверь; если пешком напрямую быстрее — выбирается оно.
  Пересадки показываются явно (`Рижская 6→11`). МЦК/МЦД/монорельс — вне покрытия.
- **Геокодинг двойной** (`geocode.py`): Nominatim → fallback Photon/komoot
  (Nominatim с нашей сети отвечает 403 на честный UA — вместо подделки UA идём
  в Photon, координаты совпали). Дом можно задать и точкой с карты (скрепка →
  Геопозиция) — тогда геокодинг вообще не нужен.
- Формула выхода: `начало первой пары − дорога − запас`. Если время прошло —
  честное «выходите сейчас». Двойного счёта нет: ожидание посадки живёт только
  внутри `ride.seconds` (покрыто тестом на равенство суммы ног итогу).

## Интерфейс
`/start` → проверка группы по живому списку (опечатки → похожие варианты) →
проверка адреса (см. ниже) или точка → карточка настроек.
Меню: «📅 Сегодня», «🗓 Завтра», «🚪 Когда выходить», «📝 Заметки», «⚙️ Настройки».
«Сегодня» показывает фокус (ближайшая пара, на которую можно попасть:
успеваешь / выходить сейчас / к началу не успеть / идёт — приедешь во столько,
останется столько) + всё расписание дня; закончились — так и пишет.
Настройки — только кнопками (группа, адрес, транспорт, запас, уведомления, язык);
после изменения карточка обновляется и дорога пересчитывается от новых данных.
Заметки — пошагово кнопками: дата (Сегодня/Завтра/выбрать) → текст →
подтверждение; просмотр, изменение, удаление, отмена на каждом шаге.
Ручные команды (`адрес …`, `транспорт …` и т.д.) оставлены как запасной путь.

## Проверка домашнего адреса до сохранения (`address_check.py`)
Ввод разбирается на город/улицу/дом/корпус-строение; кандидат геокодера
сверяется по полям: город обязан быть Москвой, улица и дом — совпасть,
корпус/строение — совпасть, если указан. Принимается только точка конкретного
дома; совпадение с улицей/районом — недостаточно. Несколько подходящих домов —
списком на выбор. Затем: «Нашёл: Москва, ул. Островитянова, д. 33А. Это ваш
дом?» — адрес и координаты сохраняются только после «да». Иначе: исправить
текст или прислать геоточку; точка подтверждается отдельно («рядом с …»,
без выдачи ближайшего дома за точное совпадение).

## Сообщения: единый вид + задел под iOS-push (`cards.py`)
Данные отдельно (EveningData/MorningData), оформление отдельно:
Telegram-шаблоны и push-шаблоны (заголовок + короткий текст с ключевым
временем). Push НЕ работает — нет APNs-ключа; только тексты и data-поля.
Эмодзи — подсказки: 🌙 вечер, 🏃 выход, 🚇 дорога, 🎒 взять, ⚠️ проблема.
Маршрут не посчитан — прямой текст без выдуманного времени выхода.

## Заметки и уведомления
Заметки — пошагово: «📝 Добавить заметку» → дата кнопками (Сегодня/Завтра/выбрать,
форматы ГГГГ-ММ-ДД и ДД.ММ.ГГГГ) → текст → подтверждение с датой; просмотр,
изменение, удаление (с подтверждением), отмена на каждом шаге. Всё состояние —
в SQLite, переживает рестарт. Вечером: число+список пар завтра
и «что взять». Утром: первая пара, корпус, дорога, время выхода — строго до
времени выхода, без дублей (факты отправки в БД переживают рестарт),
пересчёт не чаще раза в 30 мин и только за 4 ч до пары (лимиты API целее).

## Запуск
```bash
pip install -r requirements.txt
cp .env.example .env   # заполнить BOT_TOKEN (остальное уже настроено)
python -m student_bot.bot
```

Подробно для пользователей и администратора — в [GUIDE.md](GUIDE.md).

## Тесты
```bash
python -m pytest tests -q   # сейчас: 67 passed
```
Покрыто: формула выхода и «уже поздно», первая актуальная пара, разные корпуса,
смена расписания, вечерний/утренний тексты и окно отправки, поиск по станциям
(выбор минимума), равенство суммы ног итогу, CRUD заметок и персистентность
настроек/флагов отправки после «перезапуска», геокодер-фолбэк, кэш пешего
провайдера, 6 регрессионных метро-маршрутов + калибровка, честность при
недоступности API/маршрутов/неизвестном корпусе.

## Ограничения (честно)
- Метро: без расписаний/задержек/МЦК/МЦД; ожидание — статическое среднее.
- Пешие ноги — sidewalk-роутинг без учёта перекрытий и погоды.
- Отмены в API не маркируются — детектим только перечитыванием.
- Nominatim с части сетей отвечает 403 — спасает Photon-фолбэк; для продакшна
  лучше свой геокодер/OSRM с пешим профилем.
- Адреса пользователей не логируются; ключи — только в env.
