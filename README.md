# Telegram-бот «Во сколько выходить» (СТАНКИН) + iOS API

Группа + адрес один раз → расписание, время выхода с дорогой (пешком/метро через
2GIS), заметки, избранные маршруты, два уведомления (вечером «что завтра и что
взять», утром «сколько ехать и во сколько выйти»). Плюс HTTP API для iOS
Scriptable — локальные уведомления без Telegram.

Архитектура: вся логика (`schedule_client`, `normalize`, `buildings`,
`geocode`, `routing`, `exit_time`, `store`, `notifications`, `service`) не
зависит от Telegram; `bot.py` — тонкий UI-слой, `api.py` — тонкий HTTP-слой
поверх той же логики. `cards.py` — единый вид данных (Telegram-шаблоны и
push-шаблоны `{title, body, data}` для iOS).

## Данные: реальный API stankinapp.ru (проверено живыми запросами)
- `GET /api/groups` → `{"items": [...]}` — **286 групп**. Эндпоинт нестабилен
  (таймауты TLS): клиент делает до 3 попыток, затем каскад — `GROUPS_JSON_URL`
  (зеркало-JSON, любой формы) → `data/groups_cache.json` (сид из 286 групп в
  репозитории, обновляется при каждом успешном запросе).
- `GET /api/schedule?groupName=…&startDate=…&endDate=…` → пары дня.
  Поля: `date/startTime/endTime/subject/teacher/type/cabinet/slotNumber/pairs`.
- ⚠️ **Флагов отмены/переноса в API нет.** Отменённая пара просто исчезает —
  поэтому бот перечитывает расписание перед каждым расчётом, уведомлением
  и каждым вызовом iOS API (устаревшие данные не отдаются).
- Пустой день = выходной. Часовой пояс — `Europe/Moscow`.

## Корпуса и кабинеты (`buildings.yaml`, подтверждены владельцем)
API отдаёт только `cabinet`. Правила по порядку (регистр не важен):
- `Фрезер*` → ш. Фрезер, 10 ✅; номера на `0` → новый (Вадковский пер., 1) ✅;
- остальные номерные/буквенные и `ИГ-*` → старый (Вадковский пер., 3Ас1) ✅;
- `Стадион 1` → ш. Энтузиастов, 33 (точка подтверждена) ✅;
- `С/З СТАНКИН` → новый ✅; пустой `cabinet` → неизвестно.
Координаты сверены геокодерами и используются напрямую, без геокодинга.
Маршрутизируются только корпуса из белого списка `confirmed`; неизвестный
корпус → честное «адрес неизвестен», время выхода НЕ выдумывается.

## Дорога: только 2GIS, только пешком и метро (`routing.py`, проверено живьём)
Машины нет. `GIS_API_KEY` — в env (Render Dashboard / `.env`, никогда в git).
- **Пешком**: `POST routing/7.0.0/global` (`transport: pedestrian`), живьём:
  2 варианта («по основным улицам», «кратчайший»). Длительность/расстояние —
  числа API + `ui_*`-тексты; пошаговых улиц API не даёт — детали честно пустые.
- **Метро**: `POST public_transport/2.0` (`transport: ["metro"]`), живьём:
  3 варианта с ветками (`metro.line_name`), станциями посадки, ожиданиями,
  переходами (`crossing`) и «Вы на месте в …». Пешеходный ответ (`pedestrian:
  true`) и пустота → `NoMetroError` → «маршрута на метро нет, показываю пешком».
- Retry ×3 с backoff (сеть, 429/5xx; 4xx — сразу фатально), клиентский guard
  ~20 RPS при лимите демо-периода 50 RPS. Кэш двухуровневый: in-memory +
  таблица `route_cache` в Store (SQLite/PG — переживает рестарт): метро
  15 мин, пешком 6 ч; ошибки — не дольше 2 мин. Telegram (уведомления,
  ручные запросы) — `allow_cache=True`; iOS API и избранное — всегда свежий
  запрос (`allow_cache=False`), обновляя кэш.
- Формула выхода: `начало пары − дорога − запас`. Время прошло — честное
  «выходите сейчас».

## Интерфейс бота
`/start` → проверка группы по живому списку (опечатки → похожие варианты) →
проверка адреса (только Москва, дом с корпусом/строением, подтверждение «да»)
или геоточка → карточка настроек.
Меню: «📅 Сегодня», «🗓 Завтра», «🚪 Когда выходить», «⭐ Маршруты»,
«📝 Заметки», «⚙️ Настройки».
- «Сегодня»: фокус (ближайшая пара, на которую можно попасть: успеваешь /
  выходить сейчас / к началу не успеть / идёт — приедешь во столько, останется
  столько) + всё расписание дня; всё закончилось — так и пишет.
- «Когда выходить»: выбор 🚶/🚇 → все варианты от API кнопками (метро: время,
  пересадки, пешие участки; пешком: время, расстояние) → детали (станции/ветки,
  улицы) + время выхода + ⭐ Сохранить.
- «⭐ Маршруты»: избранное (SQLite) — клик пересчитывает по свежим данным,
  удаление с подтверждением.
- Настройки — только кнопками (группа, адрес, транспорт, запас, уведомления,
  язык, 🔗 Ключ для iOS); после изменения карточка обновляется и дорога
  пересчитывается. Заметки — пошагово: дата → текст → подтверждение; просмотр,
  изменение, удаление, отмена на каждом шаге.

## iOS HTTP API для Scriptable (`api.py`, тот же aiohttp-сервер)
Настройки → «🔗 Ключ для iOS» → ссылка
`https://<PUBLIC_BASE_URL>/api/v1/today?token=…` + пояснение для Scriptable.
Токен — `secrets.token_urlsafe(32)` (таблица `api_tokens`), перевыпуск одной
кнопкой (старый сразу невалиден), в логи не пишется.
- `GET /api/v1/today` — пары сегодня + фокус (выход/дорога/прибытие/verdict) +
  заметка; `GET /api/v1/tomorrow` — пары завтра + заметка (для вечернего
  уведомления); `GET /api/v1/exit-time` — только время выхода для перепроверки
  в течение дня. Формат — схема push-шаблонов: `push: {title, body, data}`.
- Каждый вызов перечитывает расписание (`fresh=True` мимо дневного кэша) и
  считает дорогу свежим запросом 2GIS; блокирующего лимита нет (лимит раз в
  30 мин — только шедулер пушей).
- Нет группы / легло расписание → `status: unavailable` + причина, без выдумок;
  плохой токен → 401.
- Идущая пара → ответ сразу предлагает следующую (`suggest_next`): предмет,
  время, **сколько ехать до неё**, во сколько выйти, `can_catch_start`.

## Уведомления
Вечером: число+список пар завтра и «что взять». Утром: первая пара, корпус,
дорога, время выхода — строго до времени выхода, без дублей (факты отправки в
БД переживают рестарт), пересчёт не чаще раза в 30 мин и только за 4 ч до пары.

## Запуск
```bash
pip install -r requirements.txt        # runtime; для тестов: -r requirements-dev.txt
cp .env.example .env                  # заполнить BOT_TOKEN и GIS_API_KEY
python main.py                        # бот (long polling) + HTTP (:$PORT/health, /api/v1/*)
```
Деплой на Render Free — Web Service: Build `pip install -r requirements.txt`,
Start `python main.py`, Health Check `/health`. Секреты (`BOT_TOKEN`,
`GIS_API_KEY`) — только в Render Dashboard; `PUBLIC_BASE_URL` — External URL
сервиса. Free-тариф засыпает без трафика: пингуйте `/health` раз в 5–10 мин
(UptimeRobot), иначе бот уснёт. Без постоянного диска `bot_data.sqlite3`
сотрётся при рестарте — для продакшена нужен Render Disk или внешняя БД.

## Тесты
```bash
python -m pytest tests -q   # сейчас: 134 passed
```
Покрыто: формула выхода и вердикты, фокус до/идёт/после, выбор корпуса и
гейт `confirmed`, честность при недоступности API/маршрутов/неизвестном
корпусе, 2GIS (кэш/TTL/retry/429/пустое метро/реальный парсинг), избранное и
миграция транспорта, токены, структура today/tomorrow/exit-time и unavailable,
401, suggest-next (идёт → следующая с дорогой), кнопки/тексты RU/EN, health.

## Ограничения (честно)
- Расписание 2GIS-метро — без живых задержек; отмена пар в API не маркируется —
  детектим только перечитыванием.
- Пешие детали 2GIS пошаговых улиц не дают; геокодер Nominatim с части сетей
  отвечает 403 — спасает Photon-фолбэк.
- Адреса и токены пользователей не логируются; ключи — только в env.
